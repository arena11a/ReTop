# รีวิวสถาปัตยกรรม ReTop / HMN v3.3 ฉบับคนไม่ใช่นักวิจัย

> เขียนให้ทุกคนอ่านรู้เรื่อง: พนักงานขาย, นักเรียน, เจ้าของร้าน — ถ้าเข้าใจ
> "ของที่ถูกคัดลอก ต้องไม่ถูกตีความ" ก็เข้าใจครึ่งหนึ่งของโมเดลนี้แล้ว

---

## 1. ปัญหาที่โมเดลนี้มาแก้

สมมติว่าเราสอน AI ให้ตอบแบบนี้:

```
user:   pip install pkg042
answer: pip install pkg042
```

หน้าที่ของ AI คือ **พิมพ์ข้อความเดิมซ้ำแบบเป๊ะๆ** จากที่ผู้ใช้พิมพ์ — ไม่ใช่
"คิดขึ้นเอง" โจทย์นี้ดูง่าย แต่สำหรับโมเดลภาษาแบบเก่ามัน**เป็นไปไม่ได้**

ทำไม? โมเดลภาษาทั่วไปทำงานแบบ "ทายคำถัดไปจากการทำนายทางสถิติ" เหมือนโหร
ที่ทายข้อความ มันไม่เคยเห็น "pkg042" มาก่อน มันจึงได้แค่**เดาแบบมั่วๆ**
(out of 40 คำถาม ได้ถูก 0 ข้อ) — ลองนึกภาพให้นักเรียนคัดลอกข้อสอบแล้วต้อง
"คัด" แต่เขาทำได้แค่ "เขียนใหม่จากที่จดจำ" ผลลัพธ์คือเบลอๆ ไม่ตรงเป๊ะ

**ปัญหาคือเชิงโครงสร้าง** ไม่ใช่แค่เรื่อง "โมเดลเล็กไป" หรือ "ฝึกนานกว่านี้"
มันเป็นข้อจำกัดของสถาปัตยกรรมเดิมที่ผสมทุกหน้าที่ไว้ในเส้นทางเดียว

## 2. วิธีแก้ของ ReTop: แยก "ถนน" สองสาย

โมเดลนี้แบ่งสมองออกเป็นสองเลนรับผิดชอบคนละอย่าง:

```
input_ids
   │
   ├─▶ ฝั่ง "ตีความ" (Working Register)
   │        คิดวิเคราะห์: สร้างบริบท, เข้าใจว่า "pip install" คือคำสั่ง
   │
   └─▶ ฝั่ง "คัดลอก" (Identity Register)
            เลนสำรองที่เก็บหน่วยความจำของคำในข้อความต้นทางไว้แบบเน้นๆ
            ทำหน้าที่แค่ "ชี้ไปที่คำที่ถูกต้องในข้อความที่เราให้ไป"

ตอนตอบ: ทั้งสองฝั่งทำงานพร้อมกัน แล้ว "ประตูสับไฟ" (gate) เป็นตัวตัดสินใจ
         มีสติ แต่ละคำที่ตอบไปว่าควรจะ "คัด" หรือควรจะ "คิด"
```

เปรียบเทียบง่ายๆ: เหมือน**นักแปล**ที่ทำงาน 2 คน
- คนที่ 1 (ฝั่งตีความ) เข้าใจภาษา เขียนประโยคใหม่ได้สละสลวย แต่อาจเขียนเลขผิด
- คนที่ 2 (ฝั่งคัดลอก) เก่งแค่ชี้เลขให้ถูกต้อง จำได้ว่าเลขผู้ใช้เขียนว่าอะไร

"ประตูสับไฟ" คอยตัดสินใจ: คำไหนควรให้คนที่ 2 ชี้ เลขก็ให้คนที่ 2 ชี้เป๊ะๆ
คำไหนต้องการภาษาใหม่ (เช่นคำว่า "Installed") ก็ให้คนที่ 1 เขียน

ผลคือ: **40/40 ข้อถูกแบบเป๊ะๆ แม้เลข 40 ตัวนั้นไม่เคยเห็นในตอนฝึก** ทำให้
การฝึกใช้เวลาแค่ประมาณ 15 นาทีบน CPU ธรรมดา

## 3. จุดแข็งของสถาปัตยกรรม (ข้อดีที่คนทั่วไปควรรู้)

### 3.1 แก้ "กำแพง" ที่สถาปัตยกรรมเดิมตีด้วยตัวเอง
โมเดลปกติมี "ฝ้าเพดาน" ติดตัว: มันลอกของเป๊ะๆ ไม่ได้ เพราะมันถนัดแต่การเดา
ReTop ไม่ได้พยายามฝึกให้มันลอกเก่งขึ้น แต่**ออกแบบให้มีเลนลอกเป็นของใหม่**
แล้วให้ "ประตูสับไฟ" เรียนรู้เองว่าจะใช้เลนไหน เมื่อไร

### 3.2 แยก "งานที่ต้องตีความ" กับ "งานที่ต้องแม่นยำ"
หลักคิดสำคัญคือ **ของที่ถูกคัดลอก ต้องไม่ถูกตีความ** — ถ้าเลขไปผ่านการ
"ตีความ" ในระบบประสาท มันจะเพี้ยน (เหมือนเล่นเกม "โทรศัพท์ต่อคำ" ข้อมูลจะ
เบลอทุกทอด) ฉะนั้นฝั่งคัดลอกคือทางลัดตรงที่ไม่ผ่านการตีความเลย
(จากการวัด: อ่านตรงจากความจำ 99% ได้แม่น ผ่านการตีความได้แค่ 14%)
เป็นบทเรียนเชิงวิศวกรรมที่ลึก: บางครั้งการ "ตัดเส้นทาง" ดีกว่าการทำให้เส้นทางเก่งขึ้น

### 3.3 ฝึกไว ใช้ทรัพยากรน้อย
- ทำงานบน CPU 4 คอร์, RAM ~4 GB
- แดตaset ไม่โหลดเข้า RAM ทั้งหมด อ่านทีละก้อน (streaming)
- ใช้ "reversible coupling" = ระหว่างฝึกกลับ gradient มันคำนวณค่ากลับมาใหม่
  แทนที่จะแอบเก็บทุกอย่างไว้ในหน่วยความจำ — ช่วยประหยัด RAM อย่างมาก

### 3.4 วงจร "ซื่อสัตย์": แยกการออกแบบ การทดสอบ และตัวเลขจริง
- ทุกการตัดสินใจทางสถาปัตยกรรมถูกเขียนอธิบายใน `docs/hmn_v3_design.md`
  พร้อม**บันทึกความล้มเหลวงวดก่อน** (ทำไมถึงทำแบบนี้ ไม่ใช่ทำแบบอื่น)
- มีไฟล์ทดสอบอัตโนมัติ (`test_hmn.py`) ที่กันไม่ให้ bug เดิมกลับมา ตัวอย่าง
  bug ที่เคยร้ายแรงที่สุด: ค่า loss "ค้าง" ตาย เพราะเอา probability
  ไปเข้า `CrossEntropyLoss` อีกที — ตอนนี้มี test ดักไว้แล้ว
- มี "การ์ดเฝ้าประตู" (`slot_v33_seed42.py`) ที่เช็คว่าโมเดลผ่าน
  **40/40 แบบไม่ยอมลด** ผ่าน = ส่งงานได้, ไม่ผ่าน = กรี๊ดให้รู้เลย
  (ค่าทุกชี้ถูก deterministic — rerun กี่รอบได้เลขเดิม)

### 3.5 มี GUI ให้จิ้มเล่นได้
เปิด 4 แท็บในเบราว์เซอร์: สร้างข้อมูล → ฝึก (ดู loss วิ่งสด) → คุยกับโมเดล →
รันการ์ดเช็คความถูกต้อง ปุ่มเดียวทำได้ทั้งระบบ ไม่ต้องมานั่งจำคำสั่ง CLI

### 3.6 "รู้ว่าไม่รู้" (honest boundaries)
โมเดลเก่งเรื่องลอกค่า แต่ไม่ใช่ "การลอก" แบบทั่วไป ตัวเลขวัดแล้วถูกต้องตามจริง:

| ลองทำอะไร | ได้ผล | อธิบายสั้นๆ |
|---|---|---|
| ตัวเลขไม่เคยเห็น (pkg060..099) | **40/40** | หัวใจของงานเต็มที่ |
| เปลี่ยนรูปแบบเป็น `pip install -r pkg042` | **40/40** | ยังเก่งแม้ปรับโครงสร้าง |
| เลข 4-5 หลัก | ~37/40 | โซ่ลอกยาวขึ้นเริ่มหลุดบางจุด |
| เลขซ้ำกัน `pkg333` | ~3/9 | เลือนลอกวน ตรวจจับจบไม่ทัน |
| เปลี่ยนคำสั่งเป็น `import pkg042` | **0/40** | ยังไม่ใช่ "การลอก" ทั่วไป — ผูกกับแม่แบบที่ฝึก |

คนอ่านจะได้เห็นครบทั้ง "เก่งตรงไหน" และ "ยังไม่เก่งตรงไหน" แทนที่จะอวยแบบเว่อร์

## 4. หน้าตาของชิ้นส่วน (เฉพาะที่ควรรู้)

- **Working Register (WR)** — สมองที่คิด/สร้างภาษา (SelectiveSSM + MoE)
- **Identity Register (IR)** — "ร่องรอยตัวอักษร" ความจำแบบเจาะจง ไม่ผ่านการตีความ
- **Dual-Head Decoder** — จุดรวมช่องทาง: `ผลลัพธ์ = (1−gate)·ฝั่งคิด + gate·ฝั่งลอก`
- **gate (ประตูสับไฟ)** — ตัวเลือกว่าแต่ละคำตอบลอกหรือคิด โดย train ด้วยเป้าลอย {0,1}
- **boundary_eos** — กติกาเลขโครงสร้าง: ทุกคำตอบหลังคำแรก "ต้องลอก" ได้ พอถึง
  แถวสุดท้าย (ต้องจบประโยค) ประตูหัก → บังคับให้หยุด นี่ทำให้การจบคำตอบ
  แม่นยำแบบเดช็อทเทนทึกไม่ต้องเสี่ยง
